## Architecture

A deterministic, seeded, god-style observation sim: bots wander a grid map, eat resource nodes and ruins, drink at water nodes, avoid danger, shelter, and reproduce on their own; the player watches and places nodes and bots. React 19 + Vite + TypeScript, Vitest, Canvas 2D for the map (`src/ui/render.ts`), SVG for the chart. Milestones M0-M6, M7a (ruins), M7b (water and thirst) and M8 (world events) are built (the MVP, trait inheritance, food left by the dead, a second need, and player-triggered events). The code is split into five layers under `src/`, and **`tests/architecture.test.ts` enforces the import rules** by scanning every source file (a file outside a layer also fails). When adding code, respect:

- `src/sim` — pure game rules. May import only other `src/sim` files (tests may also import `vitest`). Banned in non-test files: `Math.random`, `Date`, `performance.now`, `console`, browser storage, `process`, DOM globals/`fetch`, React, `node:*`. All randomness goes through the seeded named streams in `rng.ts` (`world`, `ai`, `birth`). Because sim files cannot import content, tests that need the real rules or presets live in `tests/`.
- `src/content` — data: `tuning.ts` (every behaviour number), `nodeDefs.ts`, `presets.ts`, assembled into `rules` in `index.ts`. May import sim types; no UI, persist, harness, or I/O.
- `src/harness` — Node CLI (`cli.ts`). Must not import `ui` or `persist`.
- `src/persist` — saves (M9). May import only sim types (not content), not ui/harness. `save.ts` is the versioned save format (`{version, seed, presetId, tick, hash, commands}`), `encodeSave`/`decodeSave` with strict validation and typed errors (never throws), `makeSave`; `share.ts` is the share link (base64url in the URL fragment `#run=`, capped at 12,000 characters); `autosave.ts` reads and writes the latest run through an injected storage object. Anything that needs content (does the preset exist, does the replay accept every command) is checked in `src/ui` at load time. Command key order inside a save must match the sim's (commands are part of the hashed state), so the decoder rebuilds each command from known fields in that order. Tests that need the real rules are in `tests/save.test.ts`.
- `src/ui` — React components. Must not import `harness`. `store.ts` is the session (world, speed, tool, selection, `dispatch(cmd)`, `clickMap`, `resetWorld`, and loading: `exportSave`, `startLoad`, `cancelLoad`; a load replays in slices through `replayJob.ts` and swaps the world in only when complete); `geometry.ts` (pixels/cells, picking), `tools.ts` (seven tools, keys 1-7 in button order, Esc = inspect), `labels.ts`, `chartMath.ts` and `traitMath.ts` are pure helpers (most with tests); the header holds `RunMenu`, a floating "Run & save" panel (closed by default, forced open while a load runs, results as a toast when shut) around `RunPanel` (seed form) and `SavePanel` (`autosave.ts` keeps the latest run in localStorage, `shareLink.ts` loads a `#run=` link, `download.ts` saves a file); the other panels are `Toolbar` (the tool buttons and the 1-7/Esc/D/B/P/M keys) with `ToolStatus` (hint and notice, rendered under the map), `Inspector`, `StatsStrip`, `PopulationChart`, `TraitChart`, `TraitSummary`, `DeathCauses`, `EventLog` (Depleted filter off by default), around `WorldCanvas` (draws via `render.ts`; takes children drawn over the map, used for the empty-world note). `EventsPanel` (the four world-event cards and the in-progress list) and `eventInfo.ts` (their text, keys D B P M, blocked reasons) sit under the map; plague and meteor are map tools (`tools.ts` `EVENT_TOOLS`). Styles: `styles.css` (base) and `panels.css`.

  **Layout rules (keep them when touching the UI):** `.workspace` in `panels.css` is a grid with named areas per breakpoint (phone: map, status, speed, tools, stats, panels; 901px: main column plus a 360px side column; 1100px: tools become a rail left of the map). The map must fit the first screen at 1280x800 with the controls and tools: `.map-frame` is capped by `--map-chrome` (the height of everything else, set per layout), so adjust that number if you add or remove rows above or below the map. Anything that appears or changes while playing (hint, notice, toast, menu, event chips, the empty-world note) must not change the height of anything in flow: reserve its space or float it over the page. The map frame uses `box-shadow`, not a border, so the canvas fills the box it was measured from. Chart x ticks come from `xAxisTicks` (`chartMath.ts`), never a fixed count. Keep every button at least 44px tall. Verify layout changes by measuring (`getBoundingClientRect`) at 1280x800, 1440x900, 1024x768, 768x1024, 375x812 and about 290px wide, including before/after switching tools and placing things.
- `src/main.tsx` is the app entry (not a layer). Nothing may import from the sibling `rpg/` or `trading-sim/` projects.

### Sim flow

`createWorld(seed, preset, rules)` builds a `World` (plain JSON). `step(world, rules)` advances one tick in place; `rules = { tuning, nodeDefs }` comes from `src/content`. Player commands (`commands.ts`: `applyCommand`, `checkCommand`) change the world between ticks and are recorded in `world.commands` with their tick; `replay.ts` rebuilds a run from seed + commands (same `stateHash` as the live run). `stats.ts` reads the samples (window changes, per-minute rates, trait drift; a minute is `tuning.stats.minuteTicks` ticks). Per tick, bots act in id order: perceive -> memory -> decide -> act -> metabolise -> death check, then a reproduction check for survivors. After the loop, in this order: dead bots are removed, children are spawned (`birth` stream), each dead bot leaves a ruin, resources regrow (times any drought or bounty), ruins decay (emptied ones are removed), expired world events and meteor craters are removed (`expireEvents`), then a stats `Sample` is taken every `stats.sampleEvery` ticks. `step.ts` only orchestrates; the phases live in `perception.ts` (sense + memory), `brain.ts` (utility scores: flee, seekFood, seekWater, rest, reproduce, wander), `movement.ts` (greedy steering around remembered danger), `nodes.ts` (eat, drink, regrow, danger/shelter exposure), `ruins.ts` (leave, merge and decay ruins), `metabolism.ts` (energy and thirst drain, damage, heal, age, death cause in the order danger or plague, thirst, starve, age) and `reproduction.ts`; `worldEvents.ts` holds the world events (below); `traits.ts` holds trait mutation, mean/min/max and the trait name order. Bots never read each other; they interact only through shared nodes. `stateHash` (`hash.ts`) is the determinism check: same seed and same commands must give the same hash. World events (M8): the `triggerEvent` command (drought, bounty, plague, meteor; `worldEvents.ts`, numbers in `tuning.events`) is applied between ticks, recorded and replay-safe like any command, and draws no random numbers. `World.events` holds the timed ones (kind, start and end tick, centre, radius, magnitude copied from tuning at start); an event affects ticks T+1 to T+D and `expireEvents` removes it at the end of tick T+D. A drought or bounty multiplies resource regrowth (`regrowthMultiplier` in `nodes.ts`; both at once multiply). A plague adds `Exposure.plague` damage inside its disc in the bot's metabolise step; bots do not perceive it (deliberate, see GAME_DESIGN section 7). A meteor damages and kills at command time (cause `meteor`, ruin left) and leaves a crater, a `danger` node with `WorldNode.expires` set (0 means permanent; craters and ruins do not count against `player.maxNodes`). Death cause when health runs out: `plague` if plague damage that tick was larger than danger damage, else `danger`. Caps and duplicate refusals are in `checkEvent`. `tests/events.test.ts` covers each effect, refusals, replay, and runs scripted events on seeds a..e for 12,000 ticks (no extinction). Retune the events with `npm run sim -- --event ...`. `tests/tuning.test.ts` runs the eden preset for 20,000 ticks over seeds a..j (about 30 s) and checks the population never dies out, never explodes, and swings; re-run it after any tuning change. Children inherit traits with a seeded mutation (`tuning.mutation`: rate, strength, per-trait bounds; eight `birth` draws per child, after the three for placement). Each trait has a cost in `tuning.ts` (`senseDrain`, `metabolismSpeed`, `birthCost`); retune with `npm run sim -- --seeds ... --ticks 60000`, which prints final mean traits, and check traits do not all pin to their bounds. `tests/traits.test.ts` has the inheritance, cost and selection tests. Ruins (M7a): a node kind `ruin` (amount, `decay` per tick, removed at 0) made by the sim on every death; numbers in `tuning.ruin` and `nodeDefs.ruin`. Bots seek and eat them through the resource path (`isFood` in `perception.ts`, `eat` in `nodes.ts`); a ruin never regrows, so it is not retried once remembered empty. They use no RNG, are not logged, and do not count toward `player.maxNodes` (`placedNodeCount`); the player cannot place one (`checkCommand` refuses kind `ruin`) but can remove one. `world.eaten` totals food eaten per source, and the survey and CLI print `ruin%`. Resource depletions are not logged (the log holds births, deaths and commands). `tests/ruins.test.ts` covers ruins; any new code that switches on `NodeKind` must handle `ruin` and `water` (`exposureAt` and `regrow` must skip both). Water and thirst (M7b): a node kind `water` (a permanent spring: radius only, `amount` and `capacity` stay 0, nothing is taken when a bot drinks) and `Bot.thirst` (0 to `bot.maxThirst`). Thirst falls by `bot.thirstDrain` times `max(1, metabolism) ^ bot.thirstMetabolismPower` per tick (the steep power keeps a fast metabolism from out-breeding everything, and the floor at 1 keeps a slow one from pinning the lower bound; see the comment in `tuning.ts`); `drink` in `nodes.ts` refills it; at 0 the bot dies of cause `thirst`. `brain.ts` scores `seekWater` like `seekFood` (`thirstWeight`, `thirstyBelow`, `quenchedAbove`); `chooseWater` in `perception.ts` skips a spring inside a remembered danger unless the bot is desperate (thirst under `brain.desperateBelow`). Memory keeps water in its own slots (`memory.waterCap`, on top of `memory.cap`). Founders, placed bots and newborns start with full thirst. `DeathsByCause` has four keys, so anything that lists causes (UI, survey, CLI, test stubs) must include `thirst`. `tests/water.test.ts` covers water and thirst.

### Conventions

Unit tests sit next to source as `*.test.ts`. Files open with a short header comment explaining the module's rules; keep that style. Every number that changes behaviour belongs in `src/content/tuning.ts` or `nodeDefs.ts`, not in `src/sim`. Changing RNG draw order or the tick order changes every hash; treat that as a deliberate change.
