# Architecture notes

Module walkthroughs and milestone notes for Garden of Eden, moved out of CLAUDE.md on 2026-11-19 (text unchanged). CLAUDE.md keeps the rules and points here. The design source of truth is still `doc/GAME_DESIGN.md`.

## Overview

A deterministic, seeded, god-style observation sim: bots wander a grid map, eat resource nodes and ruins, drink at water nodes, avoid predators and craters, shelter, and reproduce on their own; the player watches and places nodes and bots. React 19 + Vite + TypeScript, Vitest, Canvas 2D for the map (`src/ui/render.ts`), SVG for the chart. Milestones M0-M20, M21a (predator mechanics), M21b (predators replace the placeable danger zone; Eden has three) and M22 (four more heritable traits: sprint, longevity, hardiness, wariness) are built (the MVP, trait inheritance, ruins, water and thirst, world events, save and load, family knowledge sharing, lineage records, long-run tuning, the simulation in a Web Worker, the family tree view, heatmap overlays, aging fertility, two sexes, and an inbreeding penalty, the bloodline colour gene with a "colour bots by" control). The code is split into five layers under `src/`, and **`tests/architecture.test.ts` enforces the import rules** by scanning every source file (a file outside a layer also fails). When adding code, respect:

## Layer details

- `src/persist` — saves (M9). May import only sim types (not content), not ui/harness. `save.ts` is the versioned save format (`{version: 3, seed, presetId, sim, tick, hash, commands}`; `sim` is `SIM_VERSION` from `src/content/version.ts`, bumped on every rules or tuning change that alters hashes, and the ui words a hash mismatch as older or newer with it; a version 1 save upgrades to `sim` 1; version 3 (M21b) retired the `danger` kind from `placeNode`: `PLACEABLE_KINDS` is resource, predator, shelter, water, `upgradeSave` turns a version 2 save into 3 unchanged, but a version 1 or 2 save that places a danger zone is refused with the typed error `retired-kind` (dropping the command would shift every later node id), and in a version 3 save a danger placement is a `bad-command`; when an older save replays a command the current rules refuse, `replayFailureMessage` in `simHost.ts` words it as "made with older rules (vN) and no longer replays"), `encodeSave`/`decodeSave` with strict validation and typed errors (never throws), `makeSave(run, presetId, hash, sim)`; `share.ts` is the share link (two forms in the URL fragment: `#run2=` is base64url of raw-deflate bytes of the save JSON, what Copy share link writes whenever it is shorter, capped at 64,000 characters, about 5,000 commands fit; `#run=` is the original plain base64url, still read, capped at 12,000 when written; the marker tells them apart; `encodeShare`/`decodeShare`/`readShareFragment` are async, `parseShareFragment` is the sync marker check; a payload is unpacked with a 1,000,000-byte limit, a zip-bomb guard); `deflate.ts` is the `CompressionStream`/`DecompressionStream` wrapper (pure, no imports, never throws; web-platform streams are not a banned global in persist, so `tests/architecture.test.ts` is unchanged; if the streams are missing, links fall back to the plain form and a `#run2=` link gets a typed "cannot open compressed links" error); `autosave.ts` reads and writes the latest run through an injected storage object. `inspectAutosave` also returns the typed reason when the stored text cannot be opened (the ui, `src/ui/autosave.ts`, warns once per page load and keeps the text). Anything that needs content (does the preset exist, does the replay accept every command) is checked in `src/ui` at load time. Command key order inside a save must match the sim's (commands are part of the hashed state), so the decoder rebuilds each command from known fields in that order. Tests that need the real rules are in `tests/save.test.ts`.
- `src/ui` — React components, plus the simulation worker plumbing (see "Worker" below). Must not import `harness`. `store.ts` is the session (the page's mirror of the world, speed, tool, selection, async `dispatch(cmd)`, `clickMap`, `resetWorld`, and loading: async `exportSave`, `startLoad`, `cancelLoad`; the worker replays a load in slices through `replayJob.ts` and swaps the world in only when complete); `geometry.ts` (pixels/cells, picking), `tools.ts` (seven tools, keys 1-7 in button order, Esc = inspect), `labels.ts`, `chartMath.ts` and `traitMath.ts` are pure helpers (most with tests); the header holds `RunMenu`, a floating "Run & save" panel (closed by default, forced open while a load runs, results as a toast when shut) around `RunPanel` (seed form) and `SavePanel` (`autosave.ts` keeps the latest run in localStorage, `shareLink.ts` loads a `#run2=` or `#run=` link (async: the fragment is stripped at once, then the payload is unpacked; `shareLink.test.ts` covers it with a stand-in `window`), `download.ts` saves a file); the other panels are `Toolbar` (the tool buttons and the 1-7/Esc/D/B/P/M/L keys) with `ToolStatus` (hint and notice, rendered under the map; beside the notice sits the M19 "Place" count 1 / 10 / 50 / 200 for the five placement tools, hidden by `visibility` for other tools so its 44px row never moves anything; a count above 1 makes a click send `dispatchBatch` (`store.ts`, one `commands` message per 500) with random distinct cell centres from `bulk.ts` clustered in a disc around the clicked cell (`clusterPoints`, the disc grows when the count needs it; `spreadPoints` covers the whole map when no click position is given) (`Math.random` is fine in `src/ui`; the commands carry explicit coordinates, so saves and replays are ordinary), and the notice reads like "Placed 37 of 50 bots (cap reached)."; `bulk.test.ts`, `simHostBatch.test.ts`, store tests; 1,000 bots take about 30 ms instead of seconds), `Inspector`, `StatsStrip`, `PopulationChart`, `TraitChart`, Add bot sex picker (`BotSexPicker` in `Toolbar.tsx`, compact Auto / F / M with aria-labels beside the Place count; from 1280px wide it shares the notice row (dropped with `display` for other tools, so the row height is unchanged), below that it wraps to its own reserved row, `visibility`-hidden for other tools; `store.ts` `botSex`, page only, kept across a new world; `bulk.ts` `botCommand` and the optional `sex` argument of `bulkCommands`: a chosen sex goes on every placed bot, Auto sends no key; the sim command is `placeBot {x, y, sex?}` with `sex` the optional LAST key, absent for Auto so hashes and old saves are unchanged, `SIM_VERSION` and `SAVE_VERSION` unchanged; `checkCommand` refuses a value that is not a sex, `persist/save.ts` `readCommand` accepts and validates it; a save that has a `sex` key cannot be opened by an older build), `TraitSummary` (opens with a Females / Males count), `DeathCauses`, `EventLog` (Depleted filter off by default), around `WorldCanvas` (draws via `render.ts`; takes children drawn over the map, used for the empty-world note). `FamilyPanel` (M14, in the side column below the Inspector: the mother's line as a chain whose chips each have a father button, the focus's mother and father in its record details, the descendants tree, founder lines; with two sexes the family is a DAG: `lineage.ts` `childIndex` lists a child under both parents, `familyView` shows each record once and counts it once, `founderLines` roots are records with no kept parent and lines may overlap; pure `familyMath.ts` for rows, wording, indentation caps and tree keys; `familyFocus.ts` for which record it shows, an override that holds only while the map selection is the one it was made for; `useFamilyData.ts` for the throttled, stale-safe `queryFamily`/`queryFounders` calls; the Inspector's "Show family tree" button calls `revealFamily`; it reads lineage through the worker, never the page's `ViewWorld`; HTML lists for keyboard use, fixed-height scrolling tree box so refreshes move nothing), `EventsPanel` (the five world-event cards and the in-progress list) and `eventInfo.ts` (their text, keys D B P M L, blocked reasons) sit under the map; plague, meteor and blight are map tools (`tools.ts` `EVENT_TOOLS`). `HeatLegend` (M15, a panel in its own grid area `heat` under the map's status line: layer None/Traffic/Births/Deaths and range All time/Recent as radio groups, key H cycles the layer, the numeric legend, and the "Under cursor" readout from `hoverCell` in the store) controls the heatmap overlay that `render.ts` draws under the nodes (`heatRender.ts`); `heat.ts` is the pure side (grid, `observeWorld`, snapshots, bins, legend text; see "Heatmaps" below); `typing.ts` is the shared "typing in a field" check for the key shortcuts. Styles: `styles.css` (base) and `panels.css`.

## Worker (M13)

The sim runs in a Web Worker; the page only draws and sends messages. **Logic lives in `src/ui/simHost.ts`** (pure, DOM-free, Vitest drives it directly): `createSimHost()` owns the `World`, the load (replay) job and, from M15, the heat grid, and exposes `handle(msg): FromWorker[]` and `pumpLoad()`; `createHostRunner()` wires it to a `post` function and a scheduler. `sim.worker.ts` is a thin adapter around the runner (do not add the `webworker` lib to tsconfig; `self` is typed locally). `simClient.ts` has `createWorkerClient()` (falls back to inline, with a notice, if `Worker` is missing or fails before `ready`) and `createInlineClient()` (same host on the page's thread, `structuredClone` on every message; tests use it). `protocol.ts` holds the messages (`advance`, `command`, `reset`, `load`, `cancelLoad`, `exportSave`, `select`, `query`, `heat{layer|null, range}`, `commands{reqId, cmds}` (M19, bulk placing: applied in order with `applyCommand`, so each is recorded as a single command would be; only `placeNode`/`placeBot`, at most `MAX_BATCH` 500; one frame, one heat snapshot and one `commandsResult{reqId, results[]}` for the whole batch), `sync`; and `frame`, `commandResult`, `loadProgress`, `loadDone`, `save`, `queryResult`, `synced`, `error`, `ready`, `heatSnapshot`). Messages are handled in order, so a command is recorded at the right tick. The page keeps a `ViewWorld` (`viewWorld.ts`, `applyFrame`): per-tick data every frame (tick, nodes, bots without memory as `ViewBot`, events, totals). **Frame format for bots:** `Frame.fast.bots` is a `PackedBots` (`{count, f64, i32}`, `protocol.ts`), not an array of objects. `botColumns.ts` (pure) has `packBots` (host side, fresh arrays every frame), `unpackBots` (page side, builds fresh `ViewBot` objects every `applyFrame`, so `view.bots` changes identity every frame and consumers are unchanged), `INTENT_KINDS` (intent code table) and the layout: `f64` rows of 18 (x, y, px, py, energy, health, thirst, heading, then the first four traits in `TRAIT_NAMES` order, then the inbreeding score, then the bloodline hue (column 13), then the four M22 traits sprint, longevity, hardiness, wariness (columns 14 to 17)), `i32` rows of 13 (id, age, cooldown, generation, parentId (the mother), intent kind (`seekMate` is code 6, its target is a bot id), intent target, memoryCount, learnedCount, fatherId, sex code from `SEX_CODES`, lifespan, and from D3 the illness code (0 none, 1 exposed, 2 sick, 3 immune); -1 means null). Floats stay Float64 so the page computes the same means, samples and picks as the World; ints are exact below 2^31. The two buffers are transferred: `transferListOf(msg)` (`protocol.ts`) gives the list, `sim.worker.ts` and the inline client pass it, and `cloneFrame` (`viewWorld.ts`) does the same for tests (a transferred source is detached, so never reuse a frame's bots after posting it). A new per-bot field that the page reads every frame is a new column in both pack and unpack (and the strides), plus a line in `botColumns.test.ts`. Heat snapshots keep their own Float32Array. `fast.disease` (D3: `{infected, recovered}`, or null until the first outbreak; the page's `ViewWorld.disease` key is absent when null, like ecology) also rides every frame. `fast.ecology` (E3: the predator dens and counters, or null for a world made without ecology) rides every frame uncopied-by-transfer (it is small plain data, no transfer list); the page's `ViewWorld.ecology` key is absent when it is null. Slow data (samples, log, commands, the selected bot with memory) comes at most about 4 times a second, when paused, and after commands, selections, resets and loads. Panels and render/geometry helpers take a `ViewWorld`, never a `World`; anything the mirror lacks must come as a frame field or a `query`, not by sending the whole world. `loop.ts`/`planFrame` stay on the page and keep one `advance` in flight (ticks pile up, capped at 200). In `src/sim`, helpers that the page also calls (`checkCommand`, `takeSample`, `totalFood`, `traitStats`, ...) take a `Pick` of the fields they read; keep it that way when adding such a helper. Tests wait for answers with `settled()` from `store.ts`. The worker must change no behaviour: `npm run sim -- --seeds a,b,c --ticks 20000 --warmup 1000` before and after must match.

## Seasons in the UI (S3)

No sim change. `seasonInfo.ts` (pure, tested) wraps `seasonAt` for the stats strip's sixth tile, Season (value = Spring/Summer/Autumn/Winter by quarter or "Off"; detail = "x0.74 · 620 to winter", x being the regrowth multiplier, spelled out in the tooltip, a fixed line when off, so nothing moves). `chartMath.ts` `seasonBands(x0, x1, seasons, plotWidth)` gives the winter quarter of each year for the population chart's 12 px strip on the plot floor (not full height, so it is not read as an event band; none when seasons are off or a year is under `MIN_YEAR_PX` wide); the legend gains a "Winter strip" entry only while seasons are on.

## Predator ecology (E1 mechanics, E2 switched on)

On in Eden since E2 (`tuning.predator.ecology.enabled` true, `SIM_VERSION` 10; numbers: drain 0.02, killEnergy 60, maxEnergy 100, huntBelow 60, cubEnergy 50, cubCost 30, killsPerCub 6 (3 since P2), adultAge 1500, maxAge 12000, homeSpacing 24, recolonizeTicks 3000; a cub needs cubCost + huntBelow <= maxEnergy - drain, which `checkEcology` enforces, and cubEnergy below huntBelow). Predators are limited by digest time, not by prey, so E2 made breeding deliberately rare (about three cubs a seed, count peaks near 6); since P2 the prey rule sets the count instead (see the Predator-prey section). Controls that pin pre-ecology numbers run on `staticPredators(rules)` (`--static-predators` in the harness); `withEcology` still switches it on in tests. Mechanics: a world made with it has a world made with it has `World.ecology` (`dens`, `stats`) and each predator `hunt.life` (the keys are absent, never null, with it off, and the last in their objects); `predators.ts` has `checkEcology`, `startLife`, `addDen`, `isHungry` (used by `movePredators` and `exposureAt`: a fed predator neither targets nor bites, but still takes its one draw) and `predatorLife` (ageing, starvation, cubs, dens; called by `step` after `expireEvents`; a cub attempt takes two `predator` draws per territory try). `createWorld` and the `placeNode`/`removeNode` commands keep dens in step. `SimEventType` gained `predator` (`predatorEvent`: born, arrived, starved, aged). Tests: `tests/predatorEcology.test.ts`.

## Predators in the UI (M21c)

A predator is a `WorldNode` of kind `predator` with `hunt` (the frame's `nodes` carry it whole, so the page needs nothing extra; `ViewWorld.tick` gives the rest check `tick <= hunt.restUntil`). `render.ts` `drawPredator` draws a light chevron (`PREDATOR_FILL`, dark edge, letter V) pointing along `hunt.heading` at `predatorPosition` (`geometry.ts`: `hunt.px/py` to `x/y` by the frame's alpha, like a bot), inside a faint dashed ring at `node.radius` (the threat radius); a resting one is dimmed and gets a "z". **Picking uses the body, not the ring:** `geometry.ts` `PREDATOR_BODY_CELLS` (0.8) replaces a predator's radius in `nodeAt` (so inspect, hover and Remove all hit the body), a bot within reach still wins in `pickAt`, and a bot or node inside a ring stays clickable. The Inspector's `PredatorRows` use `predatorActivity` and `memoryCapacity` (`labels.ts`, pure, tested). No sim change; layout was measured unchanged (the tool count is still 7).

**Predator ecology in the UI (E3, no sim change, hashes and `SIM_VERSION` unchanged):** the page calls the sim's pure `isHungry`; nothing in `src/sim`, `src/content` or `src/persist` changed. `predatorInfo.ts` (pure, tested; takes the tuning as a parameter) holds `predatorLifeInfo` (energy, hunger countdowns, age, next-cub blocker in the sim's check order), `originText`, `denFor` (the sim's `homedNear` rule), `predatorCounts`, `predatorCapNotice`, `predatorChange` and `predatorSeries`. The Inspector shows a "Life" block for a predator that has a `life` (energy meter, hunger, starve countdown, age, next cub, origin with a button to a live parent) and "Fed, walking home (does not bite)" in the State row (`predatorActivity(hunt, tick, sated)`); the Home row says den or no den; a dead predator's notice says starved or died of age (from the `predator` log event). `render.ts` draws dens (`drawDen`, an arch under the nodes; dashed and fainter when empty, from `world.ecology.dens`; dens are not pickable) and a fed predator's threat ring dotted and fainter (hungry and ecology-off ones look as before). The map key has a Den row and a longer predator note. `PopulationChart` has a predator strip inside the same SVG under the plot (fixed 0 to `predator.maxCount` scale, dotted step line, dashed cap line), its height reserved whenever `tuning.predator.ecology.enabled` (a constant, so Blank just shows 0); the stats strip has a seventh "Predators" tile (count, change over a minute, cap; hover says hungry and origins). `store.ts` replaces the sim's "Too many predators" refusal with `predatorCapNotice` (who the eight are) and appends it to a bulk placement that hit the cap. The frame's `fast.ecology` (dens and counters, small) rides every frame; `ViewWorld.ecology` is absent, not undefined, without ecology, so `takeSample(view)` matches the World's.

**Predator traits in the UI (H3, no sim change, hashes and `SIM_VERSION` 13 unchanged):** a predator's `hunt.traits` and `generation` already ride the frame's nodes, so nothing in `src/sim`, `src/content`, `src/persist` or the protocol changed. `predatorInfo.ts` `predatorTraitRows(hunt, tuning)` (pure, tested; null without traits) gives sense in cells, speed per tick and stamina in ticks (the shipped number times the trait) with a `×1.15` multiplier, a trend (▲ ▼ ■, never colour alone) and a tooltip note, plus the generation; `multiplierText` / `multiplierTrend` format a multiplier. The Inspector shows them as a "Traits" key-value block under the Life block (always four rows while traits are on). `TraitSummary` has a "Predators" sub-table under the bot rows (mean, min, max and the same spread bar over `tuning.predator.traits.bounds`, header "N alive · gen max G", dashes with no predators, so the row count never changes; `labels.ts` `PREDATOR_TRAIT_LABEL` / `PREDATOR_TRAIT_HELP`); it sits below the map, so `--map-chrome` is unchanged. The Predators tile's detail text is unchanged (it is tight at 1024 wide); its hover gains the mean traits and the newest generation (`predatorTraitStats` over the frame's nodes). No TraitChart lines for predators; the chevron and picking are unchanged.

## Predator-prey rule (P1 mechanics, ON since P2)

On in Eden since P2 (`SIM_VERSION` 12, save format unchanged; `killsPerCub` went from 6 to 3 with it, since the limit now holds the count down). `tuning.predator.prey` (`enabled` true, `perPredator` 16, `minCount` 1, `leaveAfter` 500) acts only with `ecology.enabled` also true and only in a world made with both (`World.ecology.prey = {overSince, left}`, the last ecology key, absent otherwise). The predator count follows the bot count (median best-lag correlation about 0.57 at 20k ticks against -0.05 before; `tests/tuning.test.ts` has the bar) and predators still never die out (`minCount` 1). Controls that pin pre-P2 numbers run on `noPreyRule(rules)` (`--no-prey` in the harness), and the two pre-P1 hash pins also set `killsPerCub` 6 (`withEcology(rules, { killsPerCub: 6 })`, which forces the rule off). `predators.ts` `predatorLimit(botCount, tuning)` is `maxCount` with the rule off, else `min(maxCount, max(minCount, floor(bots / perPredator)))`; `checkPrey` validates the numbers (createWorld, CLI). `predatorLife` order: age/starve, leaving, cubs, dens. Cubs and arrivals are gated by the limit instead of `maxCount` (a gated parent takes no draws); over the limit for `leaveAfter` ticks the lowest-energy predator that was not player-placed (ties lowest id) leaves the map (`left` log event, no draw). `placeNode` keeps the hard `maxCount` cap. Harness: `withoutPrey`, `--no-prey`, columns `pCorr pCorrL pLag pLeft`. Tests: `tests/predatorPrey.test.ts` (pins Eden seed a at 5,000 ticks to its pre-P1 hash); `tests/variants.ts` `withPrey`, `noPreyRule`, and `withEcology` forces the rule off. The harness `--set predator.prey.enabled=false` also works.

**Prey rule in the UI (P3, no sim change, hashes and `SIM_VERSION` 12 unchanged):** `predatorInfo.ts` `predatorLifeInfo(hunt, tuning, count, botCount)` gains the cub block `'prey'` (after `'cap'`, the sim's order; Inspector text "too few bots") and a pure `preyPressure(ecology, botCount, count, tick, tuning)` gives `{limit, over, leavesIn}` from the sim's `predatorLimit` and `ecology.prey.overSince` (which already rides `fast.ecology`). The Predators tile detail reads "+1 · cap 4" (the current limit, as "cap 8" with the rule off; the fixed cap of 8 is in the hover; "room 4 / 8" and "max 2" were clipped at 1024 wide, same width as "cap 8" fits) and its hover spells out bots per predator and the leave countdown. The chart's predator strip draws the limit of each sample's population as a faint dash-dot step line (`.line-room`, no new legend row). The map key's predator note adds "leaves if bots are too few".

## Predator traits (H1 mechanics, ON since H2)

On in Eden since H2 (`tuning.predator.traits.enabled` true, `SIM_VERSION` 13, save format unchanged; mutation rate 0.5, strength 0.2, prices 0.15 / 0.3 / 0.06, bounds sense 0.75 to 1.5, speed 0.8 to 1.2, stamina 0.5 to 2; the sweep is in the GAME_DESIGN changelog; acts only with `ecology.enabled` too and only in a world made with both). No hash change with it off (`tests/predatorTraits.test.ts` pins Eden seed a at 5,000 ticks with a placed and removed predator, seed b at 20,000 ticks and `world.rng.predator`, both on `noPredatorTraits(rules)`; the harness gives the same world with `--set predator.traits.enabled=false`; controls that pin pre-H2 numbers run on `noPredatorTraits`). `tests/tuning.test.ts` checks generation, drift and no bound on the ten 20k surveys. `src/sim/predatorTraits.ts` (imports only rng and types, never predators.ts): `PREDATOR_TRAIT_NAMES` (sense, speed, stamina; the draw order, never reorder), `checkPredatorTraits` (createWorld, even when off), `traitsOn`, `startTraits` (always after `startLife`, so the keys are `life`, `traits`, `generation`; absent, never null, when off), `inheritPredatorTraits` (like `mutateTraits`: a roll then an amount per trait, six `predator` draws a cub, taken only once a territory is found, so a cub costs 2 x tries + 6 draws), `predatorTrait` (1 when absent), `predatorDrain` (`ecology.drain` itself when absent, else drain x (1 + sum of price x (trait - 1))) and `predatorTraitStats`. `movePredators` uses range = senseRadius x sense (cone and all-round), step = speed x speed trait and give-up at chaseTicks x stamina; `predatorLife` drains by `predatorDrain`. Founders, placed and arriving predators get {1,1,1}, generation 0, no draws; a cub gets generation + 1. The UI readers (`render.ts` `drawSight`, the Inspector's Sight row, `predatorInfo.ts` countdowns) use the per-predator values. Harness: `--predator-traits`, columns `pSense pSpeed pStam pGen`; `tests/variants.ts` `withPredatorTraits` and `noPredatorTraits` (`withEcology` and `staticPredators` force the traits off). Median predator generation at 60k is 3.5 (the H2 bar of 4 was not reachable with the five numbers allowed; reported, not gated).

## Mate choice (G1 mechanics, ON in Eden since G2)

`tuning.mateChoice` ({enabled true, avoidAt 0.5, lastResort false} since G2; `SIM_VERSION` 14, save format unchanged, no UI; the G1 build was off with lastResort true and changed no hash). `src/sim/kin.ts` (imports only types): `kinship(a, b)` is `lineage.relatedness` computed from the two bots' own `parentId`/`fatherId` (1 parent-child or full siblings, 0.5 half siblings, else 0; a null parent matches nothing), `avoidsKin`, and `checkMateChoice` (avoidAt in (0,1], flags booleans; `createWorld` always runs it, the CLI too). `mating.ts` `nearestMate(index, bot, radius, choice)`: `choice` null (brain passes null when off) runs the original loop; otherwise it returns the nearest non-kin female, else the nearest kin one when `lastResort`, else null (ties lowest id). `reproduction.ts` `pairMates`: off keeps the original sort; on, pairs are sorted by (kin, distance, female id, male id) and with `lastResort` false kin pairs are dropped, so a kin pair forms only when both bots are still free after the unrelated ones. No draws. Harness: `--no-mate-choice` (`withoutMateChoice`), `--set mateChoice.*` works, survey column `inb%` (inbred births over births, last column). Tests: `tests/mateChoice.test.ts` (pins Eden seed a at 5,000 and seed b at 20,000 ticks with their rng states to the pre-G1 values), `tests/variants.ts` `withMateChoice`, `noMateChoice`. G2 sweep (GAME_DESIGN changelog): the fallback settings (lastResort true) only reached 10 to 14% inbred births against an 18.4% baseline; avoidAt 0.5 with lastResort false gives 0% with births at 98.7% and no extinction, so kin never pair in Eden. Pins that belong to the pre-G2 default rules run on `noMateChoice(rules)` (cone, genes, poison, predatorEcology, predatorPrey, predatorTraits, the lineage long run, the traits selection race); the inbreeding and mateChoice unit tests use mate-choice-off rules as their base; `tests/tuning.test.ts` has a median inbred-births bar (a third of 18.4%).

**Mate choice in the UI (G3, no sim change, hashes and `SIM_VERSION` 14 unchanged):** `Frame.fast.inbredBirths` (small number, no transfer list) feeds `ViewWorld.inbredBirths`. `TraitSummary` shows a second `trait-sexes` line, "Inbred births", from `labels.ts` `inbredBirthsLabel(inbred, births)` (one decimal, a dash before the first birth) with `INBRED_BIRTHS_HELP` as its tooltip; it is `nowrap` and always present, so the panel height never moves. The Inspector's Inbred row has a tooltip. No related/unrelated note on a male's mate target: kin never pair in Eden.

## Predator sexes (PS1, mechanics, OFF)

`tuning.predator.sexes` = `{ enabled false, mateRange 120, loneAfter 3000, killsPerCub 3, crossover true }` (last key of `predator`, after `traits`; first guesses, user decision of 2026-11-21 reversing H1's "no sexes"; `SIM_VERSION` stays 15, save format 3, every hash with it off is unchanged and pinned in `tests/predatorSexes.test.ts`). Code: `src/sim/predatorSexes.ts` (imports only `types.ts` and `exactMath.ts`: `checkPredatorSexes`, `sexesOn`, `predatorAutoSex`, `startSex`, `findMate`, `predatorSexCounts`, `lastOfSex`), `predators.ts` (`predatorLife`), `predatorTraits.ts` (`crossPredatorTraits`), `world.ts`, `commands.ts`.

- **Gate and keys.** `sexesOn` is true with the rule and ecology on in a world made with both (`world.ecology.sexes` exists). Then a predator has `hunt.sex` (the last key of `PredatorState`, after `generation`), a cub of a pair has `life.fatherId` (last key of `PredatorLife`; absent on founders, arrivals, placed predators and lone cubs) and `world.ecology.sexes = { oneSexSince, mated, alone }` (last key of `PredatorEcology`, after `prey`). With the rule off none of these keys exists. `createWorld` always runs `checkPredatorSexes`, even off (the CLI too).
- **Sex of a new predator.** `predatorAutoSex(nodes)` is the sex there are fewer of among predators that have a sex, a tie gives female, no draw. Founders (node order gives female, male, female in Eden), arrivals, cubs (counted together with the cubs made so far this tick) and placed predators (`cmd.sex ?? predatorAutoSex(world.nodes)`) all use it.
- **Breeding** (`predatorLife` order unchanged: age and starve, leaving, cubs, dens). Only a female bears a cub, under the existing checks but with `sexes.killsPerCub` instead of `ecology.killsPerCub` (adult age, energy of `cubCost + huntBelow`); the prey-rule limit gate stays first, so a gated female takes no draws. She also needs a mate: `findMate` is the nearest adult male (`life.age >= adultAge`, ties lowest id) within `mateRange` of her current position. The lookup happens before the territory draws, so with no mate there is no cub and no draw. The mother pays `cubCost`; the male pays nothing and has no cooldown; `life.fatherId` is the male's id and `ecology.sexes.mated` counts the cub.
- **Lone fallback.** Each tick before the cubs `ecology.sexes.oneSexSince` is set to null when both sexes (or no predator) are alive, otherwise it keeps the tick it started (`??= tick`). Once `tick - oneSexSince >= loneAfter` any predator breeds under the E1 single-parent rule (no mate needed, the cub is the missing sex, `alone` counts it).
- **Leave guard.** When the prey rule picks who leaves, a first pass skips a predator that is the only one of its sex alive; if that leaves nobody, a second pass chooses as before. No new number, no draw.
- **Traits.** With `crossover` and a mate, per trait in `PREDATOR_TRAIT_NAMES` order one `predator` draw takes the mother's (below 0.5) or the father's value, then the unchanged `inheritPredatorTraits` mutation runs: 3 + 6 = 9 draws a cub, taken only once a territory is found. With `crossover` false or a lone cub: the mother's (or lone parent's) traits, 6 draws as before. Generation is the higher parent's plus 1.
- **Command.** `placeNode` takes an optional last key `sex` (predator only: `Only a predator can have a sex.`; value female or male, else `The sex must be female or male.`); with the rule off it is accepted and ignored (but still recorded in the command log). `persist/save.ts` reads it with the same shape as `placeBot`'s sex, so there is no `SAVE_VERSION` bump and an older build refuses such a save as a bad command.
- **Harness.** `--predator-sexes` (ecology too) and `--no-predator-sexes` (`withPredatorSexes`/`withoutPredatorSexes` in `survey.ts`), or `--set predator.sexes.*`; survey columns `pFem pMale pMated pAlone 1sex%` last (females and males alive at the end, cubs of pairs, lone cubs, percent of ticks after the warmup with only one sex alive; dashes with the rule off). Test variants: `withPredatorSexes`, `noPredatorSexes` in `tests/variants.ts`; `withEcology` and `staticPredators` force it off.
- **PS2 retune (tried, NOT shipped, OFF, `SIM_VERSION` 15, no code change).** 13 settings of mateRange / loneAfter / killsPerCub (and crossover on the best) were swept; killsPerCub 3 and mateRange 40 or less fail the predator-follows-bots bar (cubs fall from about 7 to 3 or 4 a seed over 20k ticks, median pCorrL 0.21 to 0.36 against 0.55), and killsPerCub 2 with mateRange 60 or 120 passes every 20k bar but breaks the 60k mean-caution floor on at least one seed (best candidate 120 / 1500 / 2 / crossover true, misses seed e by 0.03; crossover off is worse). Event scenes and wall time were fine; thirst deaths at 60k rose 30 to 50%. Results and the retry recipe are in the GAME_DESIGN changelog (PS2). Wall time of the sexes code is about +0%.

R3 (mechanics, off by default, `damageWeight` 0 and `centred` false, the last two keys of `tuning.resistance`): `sickDrainFor` divides the sickness damage by 1 + damageWeight x (r - anchor) (`sickDamage` takes `World.resistance` as a third argument and falls back to the plain drain for a bot with no `resist`), and `anchor` is 1 or, with `centred`, `World.resistance.founderMean`; `catchThreshold` and `sickLength` take the anchor as a last argument (default 1). `checkResistance` with `centred` needs max(catchWeight, sickWeight, damageWeight) x (founderMax - min) below 0.5, so a bot below the mean never has a factor of 0.5 or less. `ViewBot` omits `resist` (nothing in the UI reads it yet). Harness: `--no-resistance`, `--set resistance.*`, survey columns `res0 res resMax` last (founder mean, living mean and living max resist at the end; dashes with the rule off, before the first outbreak or with nobody alive). Tests: `tests/resistance.test.ts` (Eden pins a at 5,000 and b at 20,000 with it on and no outbreak, an outbreak scene pinned with it off, activation, inheritance draw counts and bounds, dose and sickness effects, upkeep, replay and JSON copy, `checkResistance`); `tests/variants.ts` `withDiseaseResistance` / `noDiseaseResistance`.

## Toxic food (T1, mechanics, OFF)

## Heatmaps (M15)

Heat lives outside the `World`, in a `HeatGrid` (`src/ui/heat.ts`, the map's size, 120 x 80 cells in Eden; per layer `traffic`/`births`/`deaths` an all-time `Float64Array` and a `recent` `Float32Array` that fades by 0.9 every 100 ticks). The `SimHost` owns it and calls `observeWorld(heat, world)` after every `step` and after every applied command (a meteor kills at command time); `createReplayJob`'s `onTick` hook calls the same observer after every step and applied command, so a load rebuilds the grid exactly (a load builds its own grid and swaps it in only when complete; a failed or cancelled load keeps the old one). It is not hashed and not saved (`src/persist` unchanged). Traffic is +1 per living bot per tick; births and deaths are the change in `totalBirths` / the death total, attributed from the newest matching `World.log` entries (they carry x and y; events that fell out of the 500-event ring are counted in `unattributed`, never put in a wrong cell). Display constants live in `heat.ts`, not `tuning.ts`. The grid is always accumulated; the page only gets a `heatSnapshot` (one layer as a `Float32Array` plus `max`, `hottest`, `total`, `runId`) while a layer is on: after a `heat` request, a command, a reset, a load, with every slow advance (paused) and otherwise at most about 4 Hz (`HEAT_INTERVAL_MS`). The store keeps `heatLayer`, `heatRange` and the latest matching `heat` snapshot (`WorldSnapshot`), and `hoverCell` in a separate small store (`useHoverCell`) so pointer moves do not wake every panel. `render.ts` draws the layer right after the grid through `heatRender.ts` (offscreen canvas, one pixel per cell, rebuilt once per snapshot; five opacity steps shared by all layers, each layer with its own hue since M19, `HEAT_RGB[layer]`: amber traffic, pink births, orange deaths, chosen to stay off the node colours; the legend swatches and the readout marker use the same hue and the layer name stays in the text; square-root scale for traffic, linear for births and deaths). Key H cycles None, Traffic, Births, Deaths (ignored while typing); it must not clash with 1-7, Esc, D, B, P, M, L. The panel reserves its height (the body's minimum height is set per breakpoint in `panels.css`; re-measure it if the legend text changes) so switching layers never moves the page, and it sits below the map so `--map-chrome` is unchanged. Tests: `heat.test.ts` (pure), `simHostHeat.test.ts` (host, including save then load giving a bit-identical grid), `heatRender.test.ts`, `storeHeat.test.ts`.

## Scenarios

A scenario is a preset with a script (`src/content/presets.ts`: `quiet`, `plague-world`, `drought-bounty`, `predator-heavy`, `hard-times`, all built by spreading `edenPreset`, so the Eden numbers stay in one place). `Preset.script` is a list of `{ tick, cmd }` (triggerEvent only); `checkScript` (`src/sim/scenario.ts`) throws in `createWorld` unless every tick is a whole number of at least 1, ticks never decrease and every command is a triggerEvent. `createWorld` copies the entries into `World.script` (pending entries, sorted; the key is absent for a plain world and deleted when the last entry has been applied; the last key of `World`, so Eden and Blank hash as before). `applyScript(world, rules)` is the last statement of `step`, after the stats row: while the first entry's tick is at most `world.tick` it is shifted off and applied with `applyCommand(world, rules, cmd, false)`. The `false` is the new `record` argument: the event starts normally (log entry, `World.events`) but is NOT pushed to `World.commands`. So tick order for a scripted event at T is: step T, scripted events at T, then player commands at T, then step T+1, the same slot as a command typed between two ticks. A refused entry is dropped and its reason returned (the sim ignores it; tests assert there are none). A save is still `{ seed, presetId, commands }`: replay rebuilds the script from the preset, so there is no save or share-link change and `SAVE_VERSION` and `SIM_VERSION` stay. An older build lacks the preset id and refuses the save with the existing "needs the X preset" message. The harness `--event` path (`makeScript`) does record its commands, so a harness run and a scenario run match in population and deaths but not in `stateHash`. UI: `RunPanel` groups the World select into Worlds and Scenarios and shows the draft preset's description with its events as a key-value list in a block of reserved height (the menu floats over the page). Tests: `tests/scenario.test.ts`.

## Sim flow

`createWorld(seed, preset, rules)` builds a `World` (plain JSON). `step(world, rules)` advances one tick in place; `rules = { tuning, nodeDefs }` comes from `src/content`. Player commands (`commands.ts`: `applyCommand`, `checkCommand`) change the world between ticks and are recorded in `world.commands` with their tick; `replay.ts` rebuilds a run from seed + commands (same `stateHash` as the live run). `stats.ts` reads the samples (window changes, per-minute rates, trait drift; a minute is `tuning.stats.minuteTicks` ticks). Per tick, `movePredators` runs first (right after `world.tick += 1`, M21a), then bots act in id order: perceive -> memory -> decide -> act -> metabolise -> death check, then a reproduction check for survivors. **Predators (M21a, `predators.ts`):** node kind `predator` with `WorldNode.hunt` (`PredatorState`, null for other kinds; hashed after `expires`); a predator takes exactly one `predator`-stream draw per tick (a wander turn) whatever its state, chases the nearest living bot outside every shelter within `predator.senseRadius`, gives up after `chaseTicks`, rests after a kill (`creditKill` in the death site of `step.ts`) and never enters a shelter radius. A bite is `Exposure.predator` from `exposureAt(world, x, y, tuning)` (pass the tuning, or predators are ignored); death cause `predator` needs bite damage strictly above danger and plague damage. Bots sense a predator by its centre, remember the sighting (third memory slot class `memory.predatorCap`, dropped after `predator.memoryTicks` in `remember`) and `knownDangers` returns danger entries and predator sightings alike; `family.shareKinds` includes `predator`. Predators do not count toward `player.maxNodes` (own cap `predator.maxCount`). Since M21b (`SIM_VERSION` 7) Eden has three, one at each old grove centre (home there; Blank has none), the player places them with the Add predator tool (key 4, the old danger tool's slot, cap `predator.maxCount`), and `checkCommand` refuses a `placeNode` of kind `danger` ("Danger zones were replaced by predators."). The `danger` NodeKind stays internal for meteor craters only (`KIND_LABEL.danger` is "crater", the death cause "Crater"); ruins decay faster only inside a crater. Predators were fixed in number until E1/E2 (see the Predator ecology section; with it off they still are). `tests/predators.test.ts` covers the mechanics. Every list of death causes (survey and CLI `predator` column, `DeathCauses.tsx`, `labels.ts`, test stubs) must include `predator`. Breeding depends on age through `fertilityAt` (M16, `reproduction.ts`, numbers in `tuning.fertility`: 0 below `bot.adultAge`, `startFraction` rising to 1 at `primeAge`, 1 until `declineAge`, falling to 0 at `fertileUntil`); a bot breeds only while fertility is above 0, and its cooldown after a birth is `ceil(reproCooldown / fertility)`. No draws. Neutral settings (startFraction 1, primeAge = adultAge, declineAge = fertileUntil = maxAge) give the pre-M16 world, which `tests/fertility.test.ts` pins by births and population (the hash can no longer match since M17 added keys). The survey and CLI have a `pAge` column: mean parent age at a birth over the kept lineage records. `SIM_VERSION` (`src/content/version.ts`) is 13. M22 traits (`TRAIT_NAMES` is senseRadius, caution, reproThreshold, metabolism, then sprint, longevity, hardiness, wariness, in that order; founders start the new four at 1): sprint multiplies a fleeing bot's speed (`movement.ts`) and costs `bot.sprintUpkeep` x (sprint - 1) energy per tick plus moveDrain x sprint on a flee step; longevity scales `Bot.lifespan` (set at birth, with the inbreeding cut) and every threshold of `fertilityAt(age, tuning, scale)` (pass `bot.traits.longevity`; the inspector stage, `fertilityLabel` and the map's child size do too), price `bot.longevityDrain`; hardiness divides all health damage (`metabolise`, meteor strike), price `bot.hardinessDrain`; wariness scales the predator radius in `knownDangers` (a copy) and the memory window in `remember`. `tests/variants.ts` `neutralTraits(rules)` pins the four at 1 with no prices (same behaviour as before M22, but the extra draws remain): control tests that pin counts run on it. The retune log is in the GAME_DESIGN changelog; the new prices are tiny on purpose (a 4% energy drain halves a lineage), and `predator.homeRange` is 11. Two sexes (M17): males find females by sensing (`mating.ts`: a per-tick grid of ready females; a ready male within his sense radius of one gets the `seekMate` intent, whose target is a bot id; bots otherwise never perceive each other; no draws). With `tuning.sex.enabled` the reproduction check only collects the survivors that end their turn in a shelter ready to breed (`meetsReproductionNeeds`); with it off a ready bot breeds alone inside the loop (`conceive`, the pre-M17 path). After the loop, in this order: dead bots are removed, (sexual mode) `pairMates` matches ready females (standing in a shelter) and ready males within `sex.mateRange` (4) by distance (ties lowest female id, then lowest male id; no draws; the mother pays `childEnergyShare` + `birthCost`, the father `sex.maleCost`), children are spawned (`birth` stream: 28 draws per sexual child since M22, angle, reach, heading, sex, eight crossover, sixteen mutation; 19 per asexual child, whose sex is `autoSex`), the lineage store is pruned if over its cap (`lineage.ts`), each dead bot leaves a ruin, resources regrow (times any drought or bounty), ruins decay (emptied ones are removed), expired world events and meteor craters are removed (`expireEvents`), then family knowledge is shared (`family.ts`), then a stats `Sample` is taken every `stats.sampleEvery` ticks. `seasons.ts` (S1 mechanics, S2 switched on in Eden with period 3000, amplitude 0.4, base 1.02, `SIM_VERSION` 9; `tuning.seasons`) is `seasonAt(tick, Pick<Tuning,'seasons'>)`: resource regrowth is multiplied by `base + amplitude * sin(2 * pi * tick / period)` (exactMath `sin`, no draws, amplitude at most 0.5; the multiplier is the literal 1 when `enabled` is false, so hashes are unchanged; `regrow(world, tuning)` in `nodes.ts` multiplies it with the drought/bounty multiplier; only resource regrowth is seasonal; `--set` and `--no-seasons` live in the harness, `src/harness/overrides.ts`; `tests/seasons.test.ts`); `step.ts` only orchestrates; **directional sensing (V1 mechanics, V2 switch-on, `tuning.perception.cone`, ON in Eden: botFront 1, botRear 0.7, predatorFront 1, predatorRear 0.35, trackTicks 10, `SIM_VERSION` 11; `noCone` in `tests/variants.ts` and `--no-cone` give the all-round world; the cone costs about 17% more survey time; the heading cos/sin was already computed once per bot per perceive call and once per predator per tick, and the follow-up hoisted the per-pair constants in `perceive` (bit-identical, hashes and `SIM_VERSION` unchanged), measured about 4% faster on the 20k a,b,c survey, so most of the cone cost is the per-pair work itself)**: `perceive(world, bot, tuning)` takes the tuning and, with the cone on, scales reach by `coneFactor(cos, front, rear)` (cos of the angle off `bot.heading`, trig once per bot, only + - * / per pair), tracks a self-seen predator for `trackTicks` ticks after it leaves the cone, and `movePredators` uses `nearestPreyCone` (cone on the predator's heading plus a lock on `hunt.targetId`); off runs the old loops byte for byte, adds nothing hashed and takes no draws; `checkPerception` validates the numbers (createWorld, CLI); `tests/cone.test.ts`; V3 UI is not built; the phases live in `perception.ts` (sense + memory), `brain.ts` (utility scores: flee, seekFood, seekWater, rest, reproduce, wander; `desperateFraction` makes a low-caution bot ignore danger avoidance at a higher hunger or thirst than a cautious one), `movement.ts` (greedy steering around remembered danger), `nodes.ts` (eat, drink, regrow, danger/shelter exposure), `ruins.ts` (leave, merge and decay ruins; a ruin inside a danger node decays `ruin.dangerDecayMult` times as fast), `metabolism.ts` (energy and thirst drain, damage, heal, age, death cause in the order danger or plague, thirst, starve, age) and `reproduction.ts`; `worldEvents.ts` holds the world events (below); `traits.ts` holds trait mutation, mean/min/max and the trait name order. `lineage.ts` (M11) keeps `World.lineage`, one compact `LineageRecord` per bot that ever lived (with `fatherId` and `sex` since M17; pruning marks both the mother and father lines) (hooks: `createWorld`, `placeBot`, `spawnChildren`, both death sites; pruned past `tuning.lineage.maxRecords`, extinct branches first, never a living bot), plus the pure queries `familyView` and `founderLines`; it is bookkeeping only (no RNG, nothing reads it back), so it never changes behaviour. Bots interact through shared nodes, with one exception (M10, `family.ts`): a parent and its own child share memory. A newborn copies the shareable part of its parent's memory at conception (`family.inherit`), and a living parent and child within `family.shareRadius` cells swap memory on ticks that are a multiple of `family.shareEvery` (a radius of 0 turns exchange off). Only `family.shareKinds` pass (not ruins); an entry is copied only if the receiver lacks the node or has an older sighting, keeping its `seenTick` and `amount`, then `trimMemory` applies the usual caps. Since M17 the child also merges its father's memory at birth (`inheritFromParents`) and exchanges with its father as well as its mother; the two parents never share with each other. `MemoryEntry.learnedFrom` is the source bot id (null when the bot saw it itself; seeing the node again clears it) and `World.familyLearned` counts entries learned (survey column `learned`). Siblings and strangers never share (they only hear second-hand through a parent). No random draws; each bot checks only its own parent, in id order, so it is linear and deterministic. `tests/family.test.ts` covers it. `stateHash` (`hash.ts`) is the determinism check: same seed and same commands must give the same hash. World events (M8): the `triggerEvent` command (drought, bounty, plague, meteor; `worldEvents.ts`, numbers in `tuning.events`) is applied between ticks, recorded and replay-safe like any command, and draws no random numbers. `World.events` holds the timed ones (kind, start and end tick, centre, radius, magnitude copied from tuning at start); an event affects ticks T+1 to T+D and `expireEvents` removes it at the end of tick T+D. A drought or bounty multiplies resource regrowth (`regrowthMultiplier` in `nodes.ts`; both at once multiply). A plague adds `Exposure.plague` damage inside its disc in the bot's metabolise step; bots do not perceive it (deliberate, see GAME_DESIGN section 7). A meteor damages and kills at command time (cause `meteor`, ruin left) and leaves a crater, a `danger` node with `WorldNode.expires` set (0 means permanent; craters and ruins do not count against `player.maxNodes`). Death cause when health runs out: `plague` if plague damage that tick was larger than danger damage, else `danger`. Caps and duplicate refusals are in `checkEvent`. `tests/events.test.ts` covers each effect, refusals, replay, and runs scripted events on seeds a..e for 12,000 ticks (no extinction). Retune the events with `npm run sim -- --event ...`. `tests/tuning.test.ts` runs the eden preset for 20,000 ticks over seeds a..j (about 30 s) and checks the population never dies out, never explodes, and swings; re-run it after any tuning change. Children inherit traits with a seeded mutation (`tuning.mutation`: rate, strength, per-trait bounds; eight `birth` draws per child, after the three for placement). Each trait has a cost in `tuning.ts` (`senseDrain`, `metabolismSpeed`, `birthCost`); retune with `npm run sim -- --seeds ... --ticks 60000`, which prints final mean traits, and check traits do not all pin to their bounds. `tests/traits.test.ts` has the inheritance, cost and selection tests. Ruins (M7a): a node kind `ruin` (amount, `decay` per tick, removed at 0) made by the sim on every death; numbers in `tuning.ruin` and `nodeDefs.ruin`. Bots seek and eat them through the resource path (`isFood` in `perception.ts`, `eat` in `nodes.ts`); a ruin never regrows, so it is not retried once remembered empty. They use no RNG, are not logged, and do not count toward `player.maxNodes` (`placedNodeCount`); the player cannot place one (`checkCommand` refuses kind `ruin`) but can remove one. `world.eaten` totals food eaten per source, and the survey and CLI print `ruin%`. Resource depletions are not logged (the log holds births, deaths and commands). `tests/ruins.test.ts` covers ruins; any new code that switches on `NodeKind` must handle `ruin` and `water` (`exposureAt` and `regrow` must skip both). Water and thirst (M7b): a node kind `water` (a permanent spring: radius only, `amount` and `capacity` stay 0, nothing is taken when a bot drinks) and `Bot.thirst` (0 to `bot.maxThirst`). Thirst falls by `bot.thirstDrain` times `max(1, metabolism) ^ bot.thirstMetabolismPower` per tick (the steep power keeps a fast metabolism from out-breeding everything, and the floor at 1 keeps a slow one from pinning the lower bound; see the comment in `tuning.ts`); `drink` in `nodes.ts` refills it; at 0 the bot dies of cause `thirst`. `brain.ts` scores `seekWater` like `seekFood` (`thirstWeight`, `thirstyBelow`, `quenchedAbove`); `chooseWater` in `perception.ts` skips a spring inside a remembered danger unless the bot is desperate (thirst under `brain.desperateBelow`). Memory keeps water in its own slots (`memory.waterCap`, on top of `memory.cap`). Founders, placed bots and newborns start with full thirst. `DeathsByCause` has four keys, so anything that lists causes (UI, survey, CLI, test stubs) must include `thirst`. `tests/water.test.ts` covers water and thirst.

## Conventions

**Bloodline colour gene (M20):** `Bot.hue` (degrees, after `lifespan`) and `LineageRecord.hue` (after `inbreeding`) are a cosmetic gene: founders and placed bots get `goldenHue(n)` (no draw), a child takes its mother's or father's hue and drifts it by up to `tuning.gene.drift` (6) degrees using only the separate `gene` stream (`src/sim/genes.ts`: 2 draws per sexual child, 1 per asexual, after the birth draws), and nothing reads it back, so behaviour is unchanged (the survey rows are identical; only hashes changed, `SIM_VERSION` 5). `tests/genes.test.ts` pins Eden seeds a and b at 5,000 ticks (births 299 / 277, population 70 / 67). UI: `botColour.ts` (pure: modes plain / bloodline / sex / trait / illness, `botFill`, `botShape`, key C check), `store.ts` `botColour {mode, trait}` + `setBotColour` / `cycleBotColour` (page only, not saved, kept across a new world), `BotColourControl.tsx` (first panel of the `heat` grid area; key C cycles, ignored while typing; the trait picker is hidden with `visibility`, and the legend line reserves its height per breakpoint in `panels.css`), `HueSwatch.tsx` (inspector Bloodline row, family tree). A frame bot gains a column only by adding it to pack, unpack and the strides. **Illness colour mode (UI only, no hash change):** a fifth mode `illness` (cycle plain, bloodline, sex, trait, illness; `ColourBot` gained optional `illnessStage`): healthy `HEALTHY_FILL` tan, exposed amber, sick red-orange, immune teal (`ILLNESS_FILL`, each at least 3:1 on the map, tested). `drawIllness` rings and dot stay on in every mode, so colour is not the only cue. The legend shows four swatches and the live sick and immune count (`outbreakSummary`) in the same reserved legend height.

**Inbreeding (M18):** a child's score comes from `relatedness` (`lineage.ts`; parent-child and full siblings 1, half siblings 0.5, else 0; no draws; a null parent matches nothing, so sexes off gives 0) in `spawnChildren`. `Bot.inbreeding` and `Bot.lifespan` sit after `sex` (hashed key order; `lifespan` is `bot.maxAge` unless inbred), `deathCause(bot, exposure)` ends a bot at its own `lifespan`, the child's health and energy are cut by `tuning.inbreeding` (lifespanLoss 0.2, energyLoss 0, healthLoss 0.2; the energy cut is 0 because any value from 0.05 up broke an event test on some seed), `World.inbredBirths` feeds the survey column `inb`. `LineageRecord.inbreeding` feeds the family panel flag. `SIM_VERSION` 4. `tests/inbreeding.test.ts` covers it.

**Retune note (M17):** the sexual world needed `bot.eatRate` 10, `bot.reproCooldown` 100, `bot.birthCost` 10 and founders' `reproThreshold` 65, with `sex.maleCost` 0, `sex.mateRange` 4 and the mate search (see GAME_DESIGN section 6 item 3b); tests that need the pre-M17 numbers use `stage1()` / `asexual()` from `tests/variants.ts`. Bot and lineage JSON gained `fatherId` and `sex`, so every state hash changed (`SIM_VERSION` 3).
